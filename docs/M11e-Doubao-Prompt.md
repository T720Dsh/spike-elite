## 二、M11e-1：优先解决打包版有画面启动

这是本轮最高优先级。M11d 的包构建成功，但 D3D 启动挂起，尚不满足普通用户交付。README 中已把“引擎/驱动根因已定位”改成“根因未明”：请保留这个事实边界。

诊断要求：

1. 先核对当前包、构建提交、引擎、配置、RHI、命令行、工作目录、插件和资源 cook 清单。不要拿旧包验证新改动。
2. 为每次启动使用独立绝对日志和明确超时，记录实际进程 PID。停止时只停止本轮启动的进程。
3. 使用同一份包做 D3D11/D3D12 对照，NullRHI 只作逻辑对照。复现后获取挂起时主线程/渲染线程/异步加载线程的调用栈，判断实际等待关系；日志最后一行不等于挂起根因。
4. 检查日志中的 DefaultTextMaterialOpaque、WorldGridMaterial 等同步/递归加载提示；排查项目构造函数中的 LoadObject、材质创建、TextRender 默认资产、字体、Cook 依赖、插件初始化、shader/IO 等路径。没有证据时不能排除项目代码与资源。
5. 建立最小入口场景或最小加载开关，逐个启用场馆、人物、TextRender、球、UI；每次只改变一个有因果依据的变量，找到最小复现。诊断开关放在 Development 路径，不要污染正常玩法。
6. 不要在没有调用栈和 shader/PSO 等待证据时把生成 upipelinecache 当成必然修复。也不要直接升级/重装引擎、修改整机驱动、删除整个用户缓存目录。

验收：新包在真实图形 RHI 下显示主菜单，进入比赛，完整走完 MatchOver → Rematch → 第二场结束 → 退出；补拍主菜单、比赛、战术 UI、结果页。至少 3 次冷启动/3 次正常退出，无永久黑屏和挂起。更新启动器，使普通用户默认进入已通过验收的包。若根因仍未解决，要给出复现、线程栈、已验证假设和剩余方向，标记该阶段未完成，不能用 NullRHI 给图形交付盖章。

## 三、M11e-2：战术 UI 的真实操作与空间语义

当前已接通按钮事件，但仍须验证完整输入链。特别检查 TacticalContactComponent::TickPlanning 中直接读取鼠标按下是否会与 UMG 选项点击争用同一输入。

1. 点击二传卡片仅选择该战术，不应同时意外确认击球。增加明确的“确认战术/准备击球”动作，或确保点击世界空白区才作为确认；卡片、滚动条、按钮区域不得被世界选点穿透。
2. 鼠标选择、Q/E/上下键选择、预览 Intent、GameMode.ActiveSetPlay 和最终执行必须是同一个索引。检查 HandleSetPlayPicked 是否及时重建 Intent/预览，不能只改变高亮。
3. 二传 13+1 每项都可通过鼠标和键盘到达；重点验收列表首项、末项、自由轨迹和背飞。选择末项时可见其高亮、说明和确认控件。滚轮在列表上用于滚动，在世界瞄准区才用于力度，不得同时触发两项。
4. 防守 8 项逐项检查实际计划值，区分“选中”和“确认”；提示清晰说明自动确认或超时默认行为。退出、暂停、回合结束之后，旧卡片事件不得改变下一回合状态。
5. 落点前后/左右按球队局部坐标解释：双方场地镜像，靠网是前场、靠端线是后场。增加能验证两侧和三条横向通道的案例。
6. 弧线低/中/高不要只用世界 Apex.Z 的 160/260 阈值；扣球触球点本来就在高处，会使几乎全部显示“高”。明确弧高是相对触球点还是飞行时间，保证三档随控制实际变化。
7. 风险提示分别处理合法界内、触网、出界、无法求解；同侧二传/接球不应被要求必须过网，否则正常传球会被误判。力度、弧线档位和轨迹风险不能仅用颜色区分。
8. 为键盘焦点实现真实可见样式。SEUiStyle 的注释曾宣称金框，但当前 ButtonStyle 没有实际焦点描边；不能以设置 SetKeyboardFocus 代替焦点视觉验收。

验收：实机操作逐项选择 14 个二传与 8 个防守选项；记录点击→高亮→Intent→执行的索引。至少覆盖 1280×720、1600×900、1920×1080 与 UI 0.8/1.0/1.4，最后一项和确认/取消始终可达。重启验证 UI 缩放和减少动态效果保存；未点应用而返回，应保留旧设置。

## 四、M11e-3：运动员比例、动画和镜头

现场已修正断肢缩放与髋连接，接下来继续做完整运动员轮廓。不要仅加球衣号码或肩膀球体就宣布模型升级完成。

1. 从正面/侧面/背面核对躯干、骨盆、大腿、小腿、鞋和手的比例、连接、地面高度。关节变换必须经过未缩放的 SceneComponent，网格缩放只决定外形尺寸。
2. 逐个验收 Idle、Run、Jump、Receive、Set、Spike、Block、Dive、Recover、Serve、RaiseHands。腿不得在倾身时留在原处，手脚不得漂浮或穿入躯干；左右腿在行走时有可辨认的交替运动。
3. 跑步、蹲伏、扑救检查足底与地面关系，动作与速度同步；Dive 需要低姿态伸手救球，并自然恢复到站立。不要把在空中倾斜一个躯干方块视为倒地救球完成。
4. 提升轮廓：可采用程序化低多边形圆角躯干、短裤、膝部/鞋轮廓、头颈、肤色手和前臂；有可用且合法的骨骼资产时可以换用，但保持动作状态/规则逻辑接口，不能引用损坏资产。
5. 前后号码从正常距离可读；球队颜色和号码始终与 roster/HUD 一致；号码随躯干而动，不穿模、反向或漂浮。
6. 第一人称保留可见手臂和击球动作；第三人称取景同时能看到人物腿、球、球网和接球目标，避免近景角色躯干遮住大半画面。
7. MatchOver 使用稳定场馆机位，避免结束时玩家背部或记录员文字恰好充满结果页背景；过渡遵守减少动态效果开关。

验收：单独制作角色姿态验收序列，至少正/侧/背 Idle、移动、抬手、拦网、二传、扑救和恢复。每张对应具体状态与角色 ID；补一段正常速度移动/击球录像或连续帧，以证明动画而非静态姿态。

## 五、M11e-4：真实场馆构图与美术

当前四周看台和自由区存在，但仍像灰色盒子：大面积空灰墙、灯光斑块、长黑台阶、彩色站立方块观众。标识和吸音板在正常机位中缺少辨识度。记录台的 TextRender 直接穿过/被记录员挡住，这个画面应判不合格。

1. 保持比赛场地尺寸和预留发球空间，装饰不得缩窄自由区或形成隐形碰撞。裁判、桌椅、替补席的位置需要有清楚的布局依据；记录台和两队替补席要形成同一侧的比赛工作区，而不是混在观众台阶里。
2. 把记录台记分牌做成有实体底板的桌上设备，面向主要比赛视线，显示 SET、双方分数/局数和发球方；坐姿记录员在后方，不遮挡。正面/斜侧截图都能读，比分变化与 HUD 同步。
3. 第一裁判台补可辨认的台阶/梯子、立柱、护栏和保护垫；第一/第二裁判姿态与球员/观众区别明确。替补席有座椅和坐姿替补，清楚分队。
4. 看台增加可见座椅、分区、通道和护栏。观众改为低成本坐姿轮廓，配色有分区和随机性，避免所有人像彩色站立柱。继续使用 ISM/HISM，不为每个观众生成 Actor。
5. 场馆增加清晰但克制的顶棚梁/灯具、墙面分区、入口和赛事标识。改善均匀照明和明暗层次，避免在墙面出现没有可见灯具来源的巨大光斑。
6. 木地板方向/纹理尺度一致，场内与自由区材质层次清楚；白线完整、稳定，不闪烁。球网保留上下沿和细网格，降低视觉遮挡，不能像厚白色栅栏盖住对侧球员。
7. 比赛球目前仍主要是黄球加环带。改进为真正可辨认的原创排球面板分割/接缝与适当粗糙度，保证近景无条带悬浮、接缝破面，远景仍易识别。不在未取得合法模型/素材的情况下宣称它是 Mikasa 官方模型。
8. 主菜单重新组织画面：明确的排球/场馆背景或程序化图形、足够大的排球图标、真正的横向分隔线，修复看起来像方块的装饰。让背景动画有排球主题，按钮和文字保持清晰；采用已有资产/代码图形即可，不需要堆叠花哨特效。
9. 设置使用统一的下拉框、滑条、按钮样式和间距；大 UI 缩放时可滚动设置页并保留返回/应用，不能把控件裁出窗口。

验收：固定机位对比修改前后场馆全景、正常游戏机位、网近景、看台近景、裁判台、记录台正面/斜面、替补席、球近景、主菜单。新增内容必须在普通游戏机位可见。测相同分辨率/相同机位的帧时间、DrawCall/Actor/ISM 数量；提供采样条件、平均与慢帧数据，不用 FPS 单点峰值替代性能结论。
