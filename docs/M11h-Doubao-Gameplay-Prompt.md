## 1. 本轮交付目标

玩家应当可以：选模式和球队 → 编辑 12 人名单与首发 → 看球员入场 → 实际上场或在场下执教 → 阅读发球员介绍 → 参与连续多拍攻防 → 申请球队暂停、换人、调战术 → 正确轮转和完成五局三胜 → 看个人/球队赛后数据 → 重赛或继续挑战。每个步骤必须影响生产比赛，不能只做静态 UI。

按以下阶段实施；每阶段完成小范围验证再进入下一阶段，避免一次重写全部 GameMode。

## M11h-1：球员身份、名单和首发权威模型（先做数据，后做 UI）

1. 新建数据驱动球员定义：稳定唯一 `PlayerId`（不随轮转/数组交换改变）、中文名称、队内号码、位置/角色、头像占位或实时模型视图、基础属性与模型外观配置。
2. 每队本轮固定 12 人：6 名场上 + 6 名替补。两队共 24 名比赛球员；这是本游戏挑战模式设计，不宣称所有正式赛事统一最多 12 人。
3. 区分 `RegisteredRoster`、本局 `StartingLineup[6]`、当前 `OnCourtLineup[6]`、`Bench`、`RotationSlot`、`ControlledPlayerId`。轮转只改变槽位/位置，不能改变身份、球衣号码或统计所属人；替补在场下不能参与触球。
4. 默认名单必须有完整原创姓名、号码、角色组合（主攻、副攻、二传、接应等），不得使用真实明星肖像/队标。号码队内唯一，首发不得重复，恰为 6 人。自由人本轮不强行冒充实现：若未做专用规则，标为未启用，普通后排防守角色不能套自由人球衣和权限。
5. 球员差异要进入真实逻辑：发球稳定、传球精度、移动/反应、拦网与救球等。避免数值直接决定命中或让 AI 瞬移；给出有界的计算公式和可复现随机 seed。
6. 名单编辑/首发预览面板显示：场上六人小球场、替补列表、名称号码角色、属性解释、非法配置原因。确认后生产比赛使用这份名单。
7. 保存与加载名单/挑战进度，带 schema 版本、默认回退和非法数据修复，不把绝对资产路径写进存档。

## M11h-2：模式选择和真正不同的游戏模式

至少交付以下四个可完整进入/退出/重赛的模式：

- **快速体验**：保留原 QuickMatch；生产菜单可选短局体验与正式五局，不把开发命令行冒充菜单玩法。
- **12 人名单挑战赛**：赛前选择首发和替补，连续 3 场原创对手（基础防守、强发球、快攻拦网）。难度与阵容/战术确实不同；胜负、阵容、统计及挑战进度可保存，失败可重试。先做三场完整闭环，不扩散成联网/抽卡/交易/无限生涯。
- **教练模式**：玩家在场下观赛和下指令；场上 12 人均由 AI 驱动。能调阵容、申请暂停、合法换人、选择发球落区/拦网与防守重点、二传分配倾向；从广播/教练席机位观察，不必须附身场上球员才能生效。
- **训练模式**：至少发球落点、接发传到目标区、二传配攻/扣球三个可重复训练项目；显示目标、操作教学、成功条件、即时反馈和训练结果，不影响正式比赛统计。失败快速重置，Esc 可退出。

每个模式建立配置对象，不在 Tick 堆叠互相冲突的命令行分支。旧 dev 测试模式与用户模式分离。

## M11h-3：球员入场、首发介绍与真实发球员弹入弹出

### 入场

- 双方球员从场馆入口分队列进入，教练与替补进入各自工作区；走位动画应有腿部运动，不能 24 人瞬移到点位。先做可验证的程序化路径/避让与步态，有合法骨骼资产再扩展。
- 10–15 秒内完成球队标识、双方首发六人姓名号码/位置介绍、站位与机位切换。镜头避开网柱、裁判塔及角色穿模。跳过按钮/Enter 长按可跳过，降动效设置保留静态介绍。
- 跳过与不跳过必须得到相同首发、比分、站位、发球员、计时和相机输入状态；入场时 AI 不能偷发球，球不在比赛中，不启动发球 8 秒。
- Rematch、菜单返回、局切换不得重复 Spawn 队员/教练/席位，也不得播放上场名单的旧数据。

### 发球员介绍

- 每局第一次发球、新的球员获得发球权/替换发球员时显示赛事转播卡片；默认约占横向 45%–50%、高度 40%–50%（可随分辨率安全区域缩放），一侧半屏，保留球网和对手主要区域。
- 内容至少包含姓名、大号码、球队/位置、本场发球次数与得分/失误、队色、球员模型或原创头像元素。数据来自当前权威发球员 ID，不能固定显示受控角色或 P1 数组索引。
- 约 0.3–0.4 秒滑入，1.2–1.8 秒停留，0.25–0.35 秒滑出，带轻微缓动/排球视觉元素。动画速度采用 UI 实时时间，与战术 TimeDilation 解耦；Esc 系统暂停时停止/恢复时继续；减少动态效果改短淡入淡出，不能闪烁。
- 保留跳过/缩短介绍设置。连续同一人发球默认只展示简短姓名号码条，避免每一分都看半屏动画。
- 介绍结束/跳过并恢复控制后，确认准备再由第一裁判鸣哨，然后开始 8 秒时限；介绍不能吞掉这 8 秒或遮住抛球击球输入。必要时用显式 `ServePresentation` 状态，而非 UI 私自暂停 GameMode。
- 动画被换人、暂停、局结束或返回菜单打断时，取消回调并用比赛/回合 ID 防止旧介绍结束后错误发球。不能重复鸣哨。

## M11h-4：球队暂停与比赛节奏（区别于 Esc 暂停）

按 [FIVB 2025–2028 规则](https://www.fivb.com/wp-content/uploads/2025/01/FIVB-Volleyball_Rules2025_2028-EN-v05.pdf) 的普通室内规则子集：每队每局 2 次球队暂停，默认每次 30 秒；只能死球且发球哨响之前申请。游戏可以提供短时长休闲预设，但必须明确为游戏规则。

- 系统暂停（Esc）冻结比赛并开放菜单，不消耗球队暂停次数；球队暂停进入独立比赛阶段，不把世界彻底 SetPause 后导致教练 UI、球员集结、镜头和倒计时无法运行。
- 两队当前场上球员走到各自替补席附近集结，显示队名、30 秒倒计时、剩余次数、比赛统计/战术建议。教练能在此设置战术/换人；替补和教练模型可见，不占用自由区关键通行线。
- 计时基准是正常比赛时钟，不受战术慢动作影响；Esc 打开时倒计时应暂停，继续后不跳秒；后台切出处理遵守游戏暂停策略。
- 请求合法性在 GameMode/比赛管理器校验，UI 只发意图；哨后/活球、额度耗尽、比赛结束等情况明确提示并拒绝，不偷偷冻结对方攻击。可提供“下个合法间歇申请”的队列，但需可取消且只执行一次。
- 倒计时结束或符合规则的游戏预设跳过后，球队回到当前轮次站位 → 准备 → 简短介绍 → 哨响 → 发球。暂停不得清空比分/触球统计、额外轮转、改变发球队或让同一分重复结算。
- 新局重置该局暂停额度；重赛重置所有比赛计数；队伍在局切换后对调半场时，席位/镜头和路径正确镜像。

## M11h-5：真正合法的换人系统

本轮首先实现普通换人，不把自由人替换混入普通换人计数：每队每局最多 6 次；首发每局下场一次、可回到原名单位置一次；替补只能替换其对应首发，且只能由该首发换回。一个请求可批量换多人；同队两次独立换人请求之间需完成一个回合。以官方 15.1、15.2、15.6 条核对，伤病例外本轮可不实现但明确限制。

- 选场上号码 → 选候补号码 → 显示合法性/配对/剩余次数/角色影响 → 预览 → 确认提交；取消不改任何数据。显示实际名字，不只显示 0–11 数组索引。
- 仅死球合法窗口请求；第一/第二裁判批准，记录员记账，球员经换人区进出后原子切换名单与控制权，绝不短暂产生场上 7 人/5 人或重复 ID。
- 新球员继承被换人的轮转槽位与发球顺序，不触发额外 side-out，不清空当前局比分。若换的是待发球员，介绍与 HUD 更新为新人；若换的是玩家控制球员，明确切换控制或留在场下，不能出现控制已 Destroy 的 Pawn。
- 替补 AI 停止触球/移动追球；候补物理碰撞不挡球，不因视觉席位身份成为第七个接球队员。场上和场下外观/号码/位置必须来自同一 roster，不继续显示旧的 10 个纯装饰假替补。
- 引入稳定比赛事件 `SubstitutionApproved/Completed`，积分/HUD/记录台/统计订阅同一事件源，拒绝时不消耗次数，不修改半套阵容。
- 自动化测试覆盖超限、错误配对、重复在场、非法阶段、换出后回归、跨局重置、发球员被换、受控球员被换、批量换人事务、轮转后换人与同一间歇重复请求。

## M11h-6：场下教练操控、队员操作与 AI 战术执行

- 教练模式提供自由鼠标、场下/广播机位、镜头切换、赛事 HUD、阵容与球员状态卡；按明确键位打开/关闭教练面板，不吞掉 Esc 系统暂停。
- 指令包括暂停、换人、发球重点落区、拦网线路、后排防守站位、二传分配（主攻/副攻/接应/后排）、风险偏好。UI 必须显示指令已下达/生效时机/失效原因，不能只是按钮选中颜色变化。
- 在安全时点应用战术，回合内可只更新战术倾向，绝不瞬移全队或改变飞行球速度。正常球员模式也能在间歇打开简化球队管理面板。
- 加入“切换受控队员/跟随球选择队员”，优先本方合适接球队员，不能控制对方/替补。保留固定球员模式选项；相机切换平滑，名称号码和轮次 HUD 同步。避免整场因球不靠近固定球员而只能看 AI 玩。
- AI 明确区分一传、二传、攻手、前排拦网、后排补位；二传选择应实际影响跑位和传球，近体快/背快/后三等战术不得全部落在同一默认点；失误和成功随属性/位置/时机变化。
- 不允许反复双触、贴球闪现、高速穿网、拦对方发球或把合法网带球统一判犯规。补“可见的规则理由”提示，区分球触网与球员触网。
- 体力采用轻量有界值，真实跑动/起跳影响、间歇/暂停恢复，候补休息；不做复杂伤病系统。合理体力差异让换人有价值，但初始数值应能完成正式比赛，不能把疲劳直接变成必失误。
- 时机辅助提供新手/标准选项，可调等待击球窗口（例如标准 0.8s、新手 1.2–1.8s），显示绿色最佳区与提前/偏晚文字，设置值进实际生产逻辑；不改变真实弹道预览和击球规则权威入口。
- 修整战术卡片底部帮助文案：当前 720p Armed 图中长说明仍可能越出半透明背景，需换行/缩短/自适应安全边界，并让真实新手能在窗口内理解和完成操作。

## M11h-7：正式比赛裁判组与反馈

- 复用 M11g 裁判塔：第一裁判站网端、记录台对面、眼线约高于网 50cm；第二裁判在记录台一侧。维持梯子、平台、防护垫、栏杆完整，不让其穿网/侵占发球自由区。
- 加入授权发球、指示得分/发球队、暂停 T 手势、换人手势等简洁程序动作与提示；依据权威事件驱动而不是随机挥手。动作完成不拥有第二套比分逻辑。
- 记录台显示与 HUD 相同的当前局、比分、局胜、发球队、暂停和换人剩余额度；人数和文字更新可读，不能只更新屏幕 HUD 而桌上记分牌保持开场 0:0。
- 可补两名边裁与旗语（界内/界外），但仅消费生产判定，不独立重判球；放在适当角区且不挡发球/救球路线。无需本轮做完整处罚/挑战视频系统。
- 哨声/鞋声/击球声/观众反馈分层，音量设置生效；不能每个 Tick 生成音效或以无来源商用音频替代。

## M11h-8：可玩性闭环、教学和赛后数据

- 新手首次比赛给分步骤教学：移动/视角 → 发球 → 接球 → 二传/攻击 → 拦网/救球 → 暂停与换人。可跳过、可重看，不叠加十几行常驻小字。
- 回合结果显示得分方与原因（落地、界外、连击、四次击球、发球超时等），1–2 秒可读后退场；关键镜头/球员卡不覆盖球路和主要控制。
- 个人统计至少发球得分/失误、扣球得分/失误、拦网得分、一传/二传/救球次数；定义从真实触球/得分事件归因，不能按随机数补赛后报表。换人后身份统计持续，跨局累加、重赛清零。
- 赛后显示每局比分、胜负、关键球员、球队/球员统计、挑战赛进度，提供重赛/下一场/返回菜单。不拼一个伪造 3:2 数组证明五局结束。
- 实际真人可玩验收：不用 devauto，测试进入比赛、移动接发、做一次二传选择并执行、选择扣球路线、至少一次防守决策/救球、暂停、换人、继续比赛、正常退出释放鼠标。若只能自动脚本玩而人不能完成，要记录为 FAIL。

## 2. 状态机与实现约束

优先扩展现有权威状态机，给出转换表并注明进入条件、计时源、取消路径。建议包含：`Entrance/LineupIntro → PreMatch → BetweenRallies → Timeout/Substitution → ResettingPositions → AwaitingReady → ServePresentation → ServiceAuthorized → ServingToss → Rally → SetOver → MatchOver`。可设计更好的分层实现，但不允许 UMG 控制比分、阵容和发球授权。

- Presentation、比赛管理、名单/换人/暂停服务、模式配置、统计各有清晰职责，不把新逻辑全部堆进 PlayerController 的开发工具分支。
- 每一延迟回调携带 MatchId/RallyId/PresentationId，菜单返回、重赛、切模式、局结束后作废。Timer/ticker/委托清理有测试。
